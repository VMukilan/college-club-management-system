## 2. Kubernetes Architecture & Security Specifications

### 2.1 Pod Security Standards: Restricted Profile
- **Namespace (`k8s/namespace.yaml`):** Labelled with `pod-security.kubernetes.io/enforce: restricted`. Any workload violating non-root execution, privilege escalation boundaries, or capability dropping is rejected by the Kubernetes admission controller.
- **Deployment Security Context (`k8s/deployment.yaml`):**
  - Pod level: `runAsNonRoot: true`, `runAsUser: 10001`, `runAsGroup: 10001`, `fsGroup: 10001`, `seccompProfile: { type: RuntimeDefault }`.
  - Container level: `allowPrivilegeEscalation: false`, `capabilities: { drop: ["ALL"] }`.

### 2.2 Identity & Access Governance (RBAC)
- **ServiceAccount (`k8s/serviceaccount.yaml`):** Configured with `automountServiceAccountToken: false` to eliminate token theft risks.
- **Role & Binding (`k8s/rbac.yaml`):** Restricts ServiceAccount operations strictly to read-only access for ConfigMaps within the `college-club` namespace.

### 2.3 Secrets & Configuration Segregation
- Non-sensitive parameters are stored in `k8s/configmap.yaml`.
- Cryptographic session keys are stored in `k8s/secret.yaml` and injected securely into container runtime environments.

### 2.4 High Availability, Self-Healing, and Elasticity
- **Replication:** 2 pod replicas managed via `RollingUpdate` strategy (`maxSurge: 1`, `maxUnavailable: 0`).
- **Health Probes:** Liveness and readiness HTTP probes continuously monitor `/login` to ensure broken pods are restarted without dropping user traffic.
- **Autoscaling (`k8s/hpa.yaml`):** HorizontalPodAutoscaler dynamically expands replica count up to 5 pods when CPU utilization exceeds 75%.

### 2.5 Zero-Trust Network Isolation (NetworkPolicy)
- **Manifest (`k8s/networkpolicy.yaml`):**
  - Ingress: Only allowed from the ingress controller (`ingress-nginx`) on port 5000.
  - Egress: Strictly restricted to internal DNS resolution (UDP/TCP port 53), preventing outbound data exfiltration or reverse-shell connections.
