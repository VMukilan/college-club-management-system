## 1. Objective
Containerize the hardened College Club Management System using Docker and Docker Compose. Enforce container security best practices including unprivileged non-root execution, minimal attack surface, least privilege kernel capabilities, CPU/memory resource constraints, automated health checking, isolated volume mounts for database persistence, and production WSGI execution. Maintain 100% test pass rate, zero code smells, and clean security scan metrics.

---

## 2. Containerization & Security Controls

### 2.1 Hardened Dockerfile
- **Base Image:** `python:3.12-slim-bookworm` (Debian slim, minimizing CVE footprint).
- **Non-Root Execution:** Dedicated unprivileged system user `appuser` (UID 10001, GID 10001) with shell set to `/sbin/nologin`. Container process executes as `USER appuser`.
- **Minimal Attack Surface:**
  - `pip install --no-cache-dir` ensures no temporary wheels or package archives remain in image layers.
  - No external packages (`curl`, `wget`) installed.
- **Native Healthcheck:** Uses Python standard library `urllib` to poll `http://127.0.0.1:5000/login` every 30 seconds.
- **Persistent Data Volume:** Directory `/app/instance` created with ownership `appuser:appgroup` and permissions `0750`.

### 2.2 Docker Compose Local Orchestration
- **Service Configuration:**
  - Container name: `college_club_management`
  - Image: `college-club-app:v0.4`
  - Ports: `5000:5000`
  - Environment: Production session configuration, database name, and port.
- **Security Options:**
  - `security_opt: ["no-new-privileges:true"]`
  - `cap_drop: ["ALL"]`
- **Resource Constraints (DoS Prevention):**
  - CPU Limit: `1.0` cores (Reservation: `0.25`)
  - Memory Limit: `512MB` (Reservation: `128MB`)
- **Volume Mounts:**
  - Dedicated Docker volume `club_db_data` mounted to `/app/instance`.

### 2.3 Artifact Filtering (`.dockerignore`)
- Prevents inclusion of `.git`, `.pytest_cache`, `tests/`, `instance/*.db`, `.env`, reports, and OS/IDE metadata in the build context.
