# Version 0.2 – Refactoring and Code Smell Reduction Report

**Course:** 24CYS401 – Secure Software Engineering  
**Project:** College Club Management System  
**Version:** `v0.2`  
**Date:** 2026-10-08  

---

## 1. Objective
Refactor and improve the maintainability, modularity, and code quality of the College Club Management System baseline created in `v0.1`. Systematically eliminate all 7 identified controlled code smells (CS01–CS07), achieve complete PEP 8 compliance, reduce automated SAST tool warnings, and maintain 100% test pass rate without breaking existing functionality.

---

## 2. Features Implemented / Maintained
All functional capabilities established in `v0.1` continue to operate seamlessly:
- **Student Portal:** Authentication, browsing clubs, joining clubs, viewing events, event registration, and announcements.
- **Coordinator Portal:** Event creation with automated notifications, event modification, member roster viewing, and announcement publishing.
- **Administrator Portal:** Club registration, coordinator assignments, and system audit trail inspection.

---

## 3. Code Changes
1. **`app/auth_decorators.py` (New):** Introduced `@login_required` and `@roles_accepted(*roles)` decorators.
2. **`app/constants.py` (New):** Defined `Role`, `MembershipStatus`, `RegistrationStatus`, and `AuditAction` classes.
3. **`app/config.py` (New):** Created structured `Config`, `DevelopmentConfig`, and `TestingConfig` classes.
4. **`app/exceptions.py` (New):** Established domain exception hierarchy (`ClubAppException`, `ValidationError`, etc.).
5. **`app/repositories.py` (Updated):** Added `ClubRepository.count()` and `EventRepository.count()` methods; formatted to strict PEP 8 standards.
6. **`app/services.py` (Updated):** Decomposed `create_event_with_notifications_and_audit` into helper methods; replaced procedural conditionals in `AuthorizationService` with declarative lookup map; integrated Python `logging`; removed dead code.
7. **`app/routes.py` (Updated):** Applied `@roles_accepted` across all role-protected endpoints; removed direct database connections; modernized error feedback.
8. **`app/__init__.py` & `app/models.py` & `app/database.py` (Updated):** Refactored to load from `Config` and follow strict PEP 8 conventions.

## 13. Next Version: Planned v0.3 Improvements
In **v0.3 (Secure Implementation)**, the application will undergo full security hardening:
1. **Enforce Object-Level Authorization (SEC02):** Restrict coordinator event modifications strictly to `event.club_id == current_user.club_id`.
2. **Centralized Server-Side RBAC Guard (SEC01):** Integrate `AuthorizationService.check_access` into business operations.
3. **Comprehensive Input Validation (SEC03):** Implement strict payload schema checks with character whitelisting and length bounds.
4. **Tamper-Evident Audit Logging (SEC05):** Expand `AUDIT_LOG` coverage to include failed logins, event modifications, and authorization rejections.
5. **Secure Authentication & Password Policies:** Enforce password complexity rules and account state validation.
